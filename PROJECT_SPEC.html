📊 Project Overview

A modern, full-stack social media application built with a unified technology stack across web and mobile platforms. The application enables users to create and share content, engage with others through likes and comments, and build their social presence through user profiles.

Technology Stack

🌐 Frontend (Web)

  • React 18+ with Vite
  • TypeScript
  • React Query for data fetching
  • React Router for navigation
  • React Hook Form for forms
  • shadcn/ui component library
  • Tailwind CSS for styling
  • JWT authentication
  • English/Myanmar i18n
  • Light/dark theme support
  • Web theme preference persists in local storage and applies a root dark class
  • Shared UI colors use light/dark theme tokens for surfaces, text, borders, and controls

⚙️ Backend

  • Node.js with Express
  • TypeScript
  • Prisma ORM
  • SQLite (dev) / PostgreSQL (prod)
  • API versioning (/api/v1/)
  • JWT authentication
  • Express Validator
  • CORS enabled
  • Rate limiting on auth
  • Upload handling for images
  • Admin endpoints for stats and moderation

📱 Mobile (React Native + Expo)

  • React Native with Expo
  • Expo Router for navigation
  • Expo UI components
  • React Query for data fetching
  • React Hook Form for forms
  • English/Myanmar i18n
  • Theme support (light/dark)
  • Secure token storage with Expo secure store
  • LAN-aware API client for physical devices and Android emulator networking

Current Implementation Status

The repository includes a working backend and web/mobile clients. Implemented features cover authentication, post and comment management, multi-level comment threads, likes, profiles, uploads, admin moderation, follow management, feed filtering, user and full-text search, backend notifications with history/read APIs, and WebSocket content updates for connected authenticated users. Mobile screens account for safe areas and keyboard-visible layouts, including a scrollable post detail body with a keyboard-aware comment composer. Notification preferences and UX polish remain future work.

📐 Scope

✅ Current MVP Scope

  • User Authentication (registration, login, JWT refresh, current-user lookup)
  • Post Management (create, view, delete posts with text and images)
  • Comments (create, delete, like, and reply at multiple levels on posts)
  • Likes & Reactions (toggle like/unlike posts and comments)
  • Real-time Content Updates (WebSocket updates for posts, comments, and likes across connected authenticated users)
  • User Profiles (view profiles, update profile details, list user posts)
  • Follow System (authenticated users can follow and unfollow other users)
  • Full-text Search (authenticated users can find public profiles, posts, and comments; the user-only endpoint remains supported)
  • Feed Filtering (Latest and Following feeds)
  • Real-time Notifications (WebSocket events and notification history/read APIs)
  • Basic Admin Moderation (stats, user list, content lists, ban actions)

🔮 Future Phases

  • Additional Enhanced Profile fields (location and website)
  • Notification UX enhancements (preferences, in-app toast patterns, notification center polish)

⚙️ Functional Requirements

Authentication (MVP)

User Registration
  • Register with email, username, and password
  • Email validation (format and uniqueness)
  • Username validation (alphanumeric, 3-20 characters)
  • Password requirements (min 8 chars, 1 letter + 1 number)
  • Password confirmation matching
  • JWT token generation upon registration
  • Automatic login after registration
User Login
  • Login with email/username and password
  • JWT token generation and storage
  • Token expiration (configurable, default 7 days)
  • Refresh token mechanism
  • Session management
  • Rate limiting (5 attempts per 15 minutes)
Password Recovery Future
  • Email-based password reset
  • Secure reset token generation
  • Token expiration (1 hour)

Post Management (MVP)

Create Post
  • Text content (max 500 characters)
  • Upload images (JPEG, PNG, max 5MB per image)
  • Max 5 images per post
  • Image validation and optimization
  • Automatic association with authenticated user
View Posts
  • Feed of all public posts (newest first)
  • Pagination (20 posts per page)
  • Infinite scroll option
  • View individual post details
  • Display author, content, images, timestamp, counts
Edit Post
  • Edit own posts within 24 hours
  • Preserve original creation timestamp
  • Update the post's updated timestamp
  • Reject edits by other users and edits after 24 hours
Delete Post
  • Users can delete their own posts
  • Admins can delete any post
  • Cascade delete comments and likes
  • Soft delete with recovery (admin only)

Comments (MVP)

Create Comment
  • Add comments to posts (max 300 characters)
  • Reply to any comment at any depth within the same post
  • Comment creation timestamp
  • Automatic association with user and post
View Comments
  • View all comments on a post
  • Pagination (10 comments per page)
  • List root comments and direct replies independently; expand replies on demand
  • Keep deleted comments as content-free placeholders when they have replies
  • Display author, content, timestamp, like count
Delete Comment
  • Users can delete their own comments
  • Admins can delete any comment
  • Soft delete with recovery (admin only)

Likes & Reactions (MVP)

Like Post
  • Toggle like/unlike on posts
  • Prevent duplicate likes
  • Real-time like count updates
  • Track which posts user has liked
Like Comment
  • Toggle like/unlike on comments
  • Prevent duplicate likes
  • Real-time like count updates
  • Track which comments user has liked

Real-time Content Updates (MVP)

WebSocket Events
  • Authenticated clients connect to /ws?token=<access-token>
  • Broadcast content.updated to all connected authenticated users after post/comment creation, post updates/deletion, comment deletion, and post/comment like or unlike actions
  • Events include resource, action, post ID, and optional comment ID; post/comment bodies and private account data are not broadcast
  • Existing notification.created events remain recipient-specific
Client Updates
  • Web and mobile clients refresh affected feeds and profile posts
  • Open post details and comments refresh when their post changes
  • Search results refresh after content changes

User Profiles (MVP)

View Profile
  • View any user's public profile
  • Display username, display name, bio, profile picture
  • Display user's post count
  • Display user's posts (sorted by creation date)
  • Pagination (20 posts per page)
Edit Profile
  • Edit display name (max 50 characters)
  • Edit bio (max 160 characters)
  • Upload profile picture (JPEG, PNG, max 2MB)
  • Profile picture validation and optimization
  • Changes apply immediately

Admin Moderation (MVP)

User Management
  • View list of all users with registration date, post count, status
  • Search users by username or email
  • Ban/unban users
  • View banned users list
Content Moderation
  • View all posts with filtering options
  • View all comments with filtering options
  • Delete any post or comment with reason logging
  • View deleted content history
Admin Dashboard
  • Overview statistics (total users, posts, comments, active users)
  • Recent activity feed
  • Quick actions for moderation

Follow System MVP

Follow User
  • Authenticated users can follow or unfollow another user
  • Follow and unfollow operations are idempotent; self-follow is prevented
  • Profiles display follower/following counts and the viewer's follow state
  • Following feed filters posts server-side by followed authors

Search MVP

Full-text Search
  • Search profiles by username, display name, or bio
  • Search non-deleted public posts by content
  • Search non-deleted comments on visible posts by content
  • Hashtags can be searched as literal content text
  • Exclude banned users and content authored by banned users
  • Never expose private account fields in results
  • Require at least two characters; paginate people, posts, and comments independently
  • Endpoint: GET /api/v1/search?q=<query>&page=<people-page>&postsPage=<posts-page>&commentsPage=<comments-page>&limit=<limit> (authenticated)
Search Clients
  • Web and mobile interfaces with debounced queries
  • Separate people, post, and comment result sections
  • Loading, empty, error, and paginated states
  • Existing user-only search endpoint remains supported

Notifications Implemented

Real-time Notifications
  • WebSocket connection for real-time updates
  • Notifications for likes on posts/comments
  • Notifications for new comments on posts
  • Notifications for new followers
  • Notification read/unread status
  • Notification count badge
  • Notification history
  • WebSocket endpoint: /ws?token=<access-token>
  • REST history/read endpoints under /api/v1/notifications
Notification Preferences Future

  • Email notifications (optional)

🌐 API Overview

Base URL

  • Development: http://localhost:3000/api/v1
  • Production: https://api.example.com/api/v1

Authentication

All protected endpoints require JWT token in Authorization header:

Authorization: Bearer <token>

Endpoints

Authentication
POST /auth/register - Register new user POST /auth/login - Login user POST /auth/logout - Logout user POST /auth/refresh - Refresh JWT token GET /auth/me - Get current user info
Posts
GET /posts - Get all posts (paginated) POST /posts - Create new post GET /posts/:id - Get single post PUT /posts/:id - Update post (future) DELETE /posts/:id - Delete post GET /posts/:id/comments - Get post comments GET /posts/:id/comments?parentId=<commentId>&page=<page>&limit=<limit> - Get direct replies
Comments
POST /comments - Create comment Body: { postId, content, parentId? } (omit parentId for a root comment) GET /comments/:id - Get single comment DELETE /comments/:id - Delete comment
Likes
POST /likes/post/:postId - Toggle like on post POST /likes/comment/:commentId - Toggle like on comment GET /likes/user - Get user's liked posts/comments
Users
GET /users - Get all users (admin) GET /users/:id - Get user profile PUT /users/:id - Update user profile PATCH /users/:id/ban - Ban/unban user (admin) GET /users/:id/posts - Get user's posts
Admin
GET /admin/stats - Get platform statistics GET /admin/users - Get all users with filters GET /admin/posts - Get all posts with filters GET /admin/comments - Get all comments with filters
File Upload
POST /upload/image - Upload image

Response Format

Success Response

{ "success": true, "data": { // Response data } }

Error Response

{ "success": false, "error": { "message": "Error message", "code": "ERROR_CODE", "details": {} } }

Pagination

GET /posts?page=1&limit=20 Response: { "success": true, "data": { "items": [], "pagination": { "page": 1, "limit": 20, "total": 100, "totalPages": 5 } } }

🔄 Workflows

User Registration Workflow

  1. User navigates to registration page
  2. User enters email, username, password, and password confirmation
  3. Client validates input format
  4. Client sends registration request to API
  5. Server validates uniqueness and creates user account
  6. Server generates JWT token
  7. Server returns token and user data
  8. Client stores token and redirects to feed
  9. User is automatically logged in

Post Creation Workflow

  1. User clicks "Create Post" button
  2. Create post modal opens
  3. User enters text content (optional)
  4. User uploads images (optional, max 5)
  5. Client validates content and images
  6. Client previews post
  7. User clicks "Post"
  8. Client sends post data to API
  9. Server validates and creates post
  10. Server returns created post
  11. Client updates feed with new post
  12. Modal closes and success message displays

Like Interaction Workflow

  1. User clicks like button on post or comment
  2. Client checks current like status
  3. Client sends toggle request to API
  4. Server updates like status
  5. Server returns updated like count and status
  6. Client updates UI optimistically
  7. Like button animates and count updates

Comment Creation Workflow

  1. User opens comment section on post
  2. User enters comment text
  3. Client validates input
  4. User clicks "Comment"
  5. Client sends comment to API
  6. Server creates comment
  7. Server returns created comment
  8. Client adds comment to list
  9. Comment count updates

Comment Reply Workflow

  1. User chooses Reply on any comment
  2. Client submits the reply with the post ID and parent comment ID
  3. Server verifies the parent belongs to the same post and is not deleted
  4. Client refreshes the affected thread and displays the reply
  5. Users can expand and paginate direct replies at every nesting level

Profile Editing Workflow

  1. User navigates to their profile
  2. User clicks "Edit Profile"
  3. Edit profile form opens with current data
  4. User modifies display name, bio, or profile picture
  5. Client validates input
  6. User clicks "Save"
  7. Client sends update request to API
  8. Server updates user profile
  9. Server returns updated user data
  10. Client updates profile display
  11. Success message displays

Admin Moderation Workflow

  1. Admin navigates to admin dashboard
  2. Admin views content moderation section
  3. Admin filters content (by user, date, type)
  4. Admin selects content to review
  5. Admin reviews content details
  6. Admin clicks "Delete" with optional reason
  7. Client sends delete request to API
  8. Server soft-deletes content
  9. Server logs deletion reason and admin ID
  10. Client updates content list
  11. Content marked as deleted
